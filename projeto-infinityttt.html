Infinity Tic-Tac-Toe

Sincronização de Estado em Tempo Real com Servidor Autoritativo

Node.js TypeScript Socket.io Express Event-Driven Authoritative Server

O Problema

Aplicações multiplayer simples geralmente confiam no cliente para atualizar o estado do jogo. Isso funciona em cenários locais, mas quebra completamente em ambiente real: latência, concorrência e inconsistência entre clientes.

O resultado de confiar no cliente é um sistema não determinístico e vulnerável a manipulações, onde dois jogadores podem ver estados diferentes da mesma partida.

A Decisão: Servidor Autoritativo

Para resolver isso, implementei um modelo de Servidor Autoritativo. O cliente foi reduzido a um emissor de intenções e um renderizador de estado, enquanto toda a regra de negócio reside exclusivamente no backend.

Ciclo de vida de um movimento: Validação centralizada e Broadcast síncrono.

Lógica do Modo Infinito

No modo "Infinity", o servidor gerencia uma fila circular de peças. Quando um jogador atinge o limite de 3 peças, a mais antiga é removida automaticamente antes da nova ser validada.

Fluxograma da regra de negócio: Identificação e remoção da peça mais antiga.
typescript – Implementação da Regra

function processMove(state, move) {
    const playerMoves = state.history.filter(m => m.symbol === move.symbol);

    // Regra do modo infinito: limite de peças
    if (playerMoves.length >= 3) {
        const oldest = playerMoves[0];
        state.board[oldest.position] = null; // Libera a casa antiga
    }

    state.board[move.position] = move.symbol;
    return state;
}

Controle de Concorrência

Como múltiplos clientes emitem eventos simultaneamente, o servidor atua como o ponto de serialização, garantindo que as jogadas sejam processadas em ordem estrita.

  • Verificação de Turno: Rejeita comandos de quem não está na vez.
  • Single Source of Truth: O estado em memória do servidor sobrepõe qualquer estado local do cliente.
  • Race Condition Prevention: Operações atômicas no processamento da fila de eventos do Socket.io.
typescript – Validação e Serialização

socket.on('make_move', ({ position, roomId }) => {
    const game = roomManager.getGame(roomId);

    if (!game || game.turn !== socket.id) return; // Bloqueio autoritativo

    const updatedState = game.executeMove(position);
    io.to(roomId).emit('update_game', updatedState);
});

Resultado e Trade-offs

A arquitetura prioriza a integridade do jogo. Embora exija mais processamento do servidor e gestão de estado em memória, o resultado é uma experiência multiplayer justa e tecnicamente sólida.

O que esse projeto demonstra

  • Design de sistemas distribuídos em tempo real.
  • Gerenciamento de concorrência e sincronização de estado.
  • Arquitetura orientada a eventos com Socket.io.
  • Aplicação de lógica de negócio complexa no Backend.
