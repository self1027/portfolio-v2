Pipeline de Áudio em Tempo Real para Tradução e Renderização em Libras

Node.js WebSockets FFmpeg Vosk Google Cloud STT VLibras Three.js

O Problema

Tradução de fala para Libras geralmente não funciona em tempo real. O atraso entre captura, processamento e renderização quebra a comunicação.

O desafio não era traduzir áudio — era manter um fluxo contínuo entre captura → processamento → interpretação → renderização sem perder sincronização.

O Desafio Técnico

O sistema precisava garantir:

  • Baixa latência ponta a ponta
  • Qualidade de áudio suficiente para STT
  • Pipeline contínuo com garantia de entrega de chunks
  • Inicialização segura do processamento

A Decisão

Dividi o pipeline entre cliente e servidor.

O cliente ficou responsável por pré-processar o áudio, reduzindo ruído antes do envio.

O servidor assumiu o papel de orquestrador do pipeline, controlando quando o processamento pode começar.

O pipeline só inicia quando os dados estão consistentes.

Pipeline de Áudio (Cliente)

Antes de enviar qualquer dado, o áudio é tratado para aumentar a precisão dos motores de reconhecimento.

Pré-processamento

  • high-pass(300Hz) → remove ruído de baixa frequência
  • notch(60Hz) → elimina interferência elétrica
  • compressor → estabiliza o volume

Esse pipeline é implementado diretamente no cliente usando Web Audio API, garantindo que o áudio já chegue tratado ao servidor antes da transcrição.

javascript – Pipeline no cliente

source.connect(highpass)
      .connect(notch)
      .connect(compressor)
      .connect(processor);

Controle de Inicialização (Servidor)

O servidor não processa áudio imediatamente.

O servidor inicializa o pipeline apenas após receber os metadados necessários. Enquanto isso, os chunks são armazenados temporariamente em buffer, evitando perda de dados e inconsistência durante a fase de setup.

  • Evita processamento com configuração incorreta
  • Garante consistência do stream
  • Remove perda de dados inicial
javascript – Buffer de segurança

if (isPipelineInitialized) {
    ffmpeg.pushAudio(data);
    return;
}

audioBuffer.push(data);
initPipeline(FALLBACK_SAMPLE_RATE);

Esse controle evita condições de corrida e garante que nenhum dado seja processado com configuração incompleta.

Pipeline de Tradução e Renderização

Após transcrição, o texto é transformado em uma sequência interpretável para o avatar, mantendo sincronização temporal com o áudio original.

O desafio aqui não é só tradução, mas manter a fluidez da renderização em tempo real.

Sincronização entre transcrição, tradução e renderização do avatar em tempo real.

Trade-offs

  • Maior uso de CPU no cliente (DSP)
  • Dependência de serviços externos
  • Pipeline mais complexo que batch processing

A decisão foi priorizar tempo real e consistência em vez de simplicidade.

Resultado

O sistema mantém um fluxo contínuo de tradução com baixa latência, tornando a comunicação mais natural.

O que esse projeto demonstra

  • Design de pipeline em tempo real
  • Processamento de áudio no cliente
  • Controle de estado e sincronização de stream no backend
  • Integração entre múltiplos serviços
